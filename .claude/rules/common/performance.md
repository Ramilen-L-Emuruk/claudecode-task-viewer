# パフォーマンス最適化

## モデル選択戦略

**軽量モデル**（上位モデルの9割程度の能力、低コスト）:
- 軽量エージェント（高頻度呼び出し）
- ペアプログラミング・コード生成
- マルチエージェントシステムのワーカー

**標準モデル**（最良のコーディングモデル）:
- メインの開発作業
- マルチエージェントワークフローのオーケストレーション
- 複雑なコーディングタスク

**最上位モデル**（最深の推論）:
- 複雑なアーキテクチャ判断
- 最大限の推論が必要な場面
- 調査・分析タスク

## コンテキストウィンドウ管理

コンテキストの最後20%に入ったら避けるべきタスク:
- 大規模リファクタリング
- 複数ファイルにまたがる機能実装
- 複雑なインタラクションのデバッグ

コンテキスト感度が低いタスク:
- 単一ファイルの編集
- 独立したユーティリティ作成
- ドキュメント更新
- 単純なバグ修正

## ビルドトラブルシューティング

ビルド失敗時:
1. **build-error-resolver** エージェントを使用
2. エラーメッセージを分析
3. 段階的に修正
4. 修正ごとに検証

具体的なビルドコマンドは言語・ツールチェーンに依存する（`rules/java/` 等の言語別ルールを参照）。
