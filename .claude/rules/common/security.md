# セキュリティガイドライン

## 必須セキュリティチェック

コミット前に確認:
- [ ] ハードコードされたシークレットがない（API キー、パスワード、トークン）
- [ ] 全ユーザー入力がバリデーション済み
- [ ] SQL インジェクション対策（パラメータ化クエリ、ORM/クエリビルダーの適切な使用）
- [ ] XSS 対策（テンプレートエンジンでの適切なエスケープ処理）
- [ ] CSRF 対策の有効化（利用フレームワークのCSRF機構）
- [ ] 認証・認可の検証
- [ ] エラーメッセージが機密データを漏洩しない
- [ ] ログ出力に認証情報（パスワード・トークン等）を含めない

## シークレット管理

- ソースコードにシークレットを絶対にハードコードしない
- 環境変数または設定ファイル（`.env`、`application.yml` 等）を使用
- `.gitignore` にシークレットを含むファイルを追加
- 漏洩した可能性のあるシークレットはローテーション

> 言語・フレームワーク固有のセキュリティ対策（例: Java/Spring の `PreparedStatement`、Spring Security 設定等）は `rules/java/security.md` 等の言語別ルールを参照。

## セキュリティ対応プロトコル

セキュリティ問題発見時:
1. 即座に停止
2. **security-reviewer** エージェントを使用
3. CRITICAL の問題はすべて修正してから続行
4. 漏洩したシークレットをローテーション
5. コードベース全体で類似の問題を確認
