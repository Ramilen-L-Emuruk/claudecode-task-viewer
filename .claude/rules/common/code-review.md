# コードレビュー基準

## 目的

コードレビューにより品質・セキュリティ・保守性を確保する。

## レビュータイミング

**必須レビュートリガー:**

- コードの記述・修正後
- 共有ブランチへのコミット前
- セキュリティ関連コード変更時（認証、ユーザーデータ）
- アーキテクチャ変更時
- プルリクエストのマージ前

## レビューチェックリスト

### コード品質（code-reviewer エージェント担当）

- [ ] メソッドが簡潔で単一責任であること（50行以下目安）
- [ ] クラスが適切な凝集度を保っていること（800行以下目安）
- [ ] 深いネスト（4段階以上）が回避されていること
- [ ] エラーが明示的にハンドリングされていること
- [ ] ハードコードされたシークレットがないこと
- [ ] デバッグ用の出力（`print`/`console.log` 等）が残っていないこと
- [ ] 新機能に対するテストが存在すること

### コメント・ドキュメンテーションコメント（comment-analyzer エージェント担当）

- [ ] ドキュメンテーションコメント（JavaDoc、docstring 等）のパラメータ・戻り値・例外の説明が実装と一致していること
- [ ] コメントが古くなっていないこと（コードとの乖離がないこと）
- [ ] public API にドキュメンテーションコメントが存在すること

### 指標・条件が本体からずれていないか（code-reviewer エージェント担当）

同じ事実を 2 箇所で別の言葉・別の尺度で表すと、範囲がずれる。**ずれは動かすまで見えない**ため、静的に捕まえる最初の機会がここ。

- [ ] ある資源・状態を「使っている」と表す条件式が、**消費側が実際に使っている述語をそのまま持ってきたもの**であること（言い換えた瞬間にずれる）
- [ ] 状態を列挙する条件（`== Paused` 等）が、その列挙型の**全値**について妥当であること。例外的な遷移を見落としやすい
- [ ] 事実を**観測しやすい代理値で置き換えていない**こと（「作り直された」を別フィールドの変化で、「出力できていない」を復旧処理の失敗回数で代用する類）。代理値は必ずどこかで本体とずれる
- [ ] **異常時に自身の周期が乱れるループ**の異常判定が、回数ではなく**経過時間**で行われていること（1 周が伸びた分だけ待ち時間も伸び、意図の何十倍も無言で待つ）。周期が異常に影響されないリトライ上限・サーキットブレーカーは対象外で、回数が正しい
- [ ] **寿命の違うオブジェクトに同じフラグ設計を当てていない**こと（短命なオブジェクトの「一度だけ記録する」フラグを長命なオブジェクトへ真似ると、「一度きり」が事実上「再起動まで二度と」になる）

> 言語固有のスタイルチェック（フォーマット・命名規約・レガシー API の置き換え等）は `rules/java/code-review.md` 等の言語別ルールを参照。

## セキュリティレビュートリガー

**以下の変更時は security-reviewer エージェントを使用:**

- 認証・認可コード
- ユーザー入力処理
- データベースクエリ
- ファイルシステム操作
- 外部 API 呼び出し

## レビュー重要度レベル

| レベル | 意味 | アクション |
|-------|------|----------|
| CRITICAL | セキュリティ脆弱性・データ損失リスク | **ブロック** — マージ前に必ず修正 |
| HIGH | バグまたは重大な品質問題 | **警告** — マージ前に修正すべき |
| MEDIUM | 保守性の懸念 | **情報** — 修正を検討 |
| LOW | スタイルや軽微な提案 | **注記** — 任意 |

## エージェントの使い分け

| エージェント | 担当範囲 | 使用条件 |
|-------------|---------|---------|
| **reviewer** | 言語固有のコードスタイル: フォーマット、ドキュメンテーションコメント、コード規約（詳細は言語別ルール） | **毎回**（コード変更時は必須） |
| **code-reviewer** | コード品質: セキュリティ、品質、パフォーマンス、ベストプラクティス | **毎回**（コード変更時は必須） |
| **comment-analyzer** | コメント・ドキュメンテーションコメントの正確性・完全性・コードとの一致 | コメント・ドキュメンテーションコメントの追加・変更時 |
| **security-reviewer** | セキュリティ専門: OWASP Top 10、シークレット検出 | セキュリティ関連の変更時・コミット前 |

> フレームワーク固有の専門レビュー（例: Java/Spring Boot の `java-reviewer`）は `rules/java/code-review.md` 等の言語別ルールを参照。

> **並列実行を推奨**: reviewer + code-reviewer は常に並列で起動する。フレームワーク固有レビューア、comment-analyzer、security-reviewer は該当する変更がある場合に追加で並列起動する。

## 承認基準

- **承認**: CRITICAL・HIGH の問題なし
- **警告**: HIGH の問題のみ（注意してマージ可）
- **ブロック**: CRITICAL の問題あり — マージ前に修正必須
